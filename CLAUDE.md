# CLAUDE.md — pvankatwyk.github.io

Personal academic/professional portfolio for Peter Van Katwyk, Ph.D. candidate at Brown University. The site lives at [pvankatwyk.com](https://pvankatwyk.com) and is hosted on GitHub Pages.

## Tech Stack

- **Static site generator**: Jekyll 3.10.0 (Ruby)
- **Theme**: [Minimal Mistakes](https://github.com/mmistakes/minimal-mistakes) (`mmistakes/minimal-mistakes`), remote theme, `dirt` skin
- **Markup**: Markdown (kramdown + GFM), YAML front matter, SCSS
- **Hosting**: GitHub Pages — auto-builds on push to `master`
- **Custom domain**: `pvankatwyk.com` via [CNAME](CNAME)

## Local Development

```sh
# Prerequisites: Ruby installed
bundle install
bundle exec jekyll serve -l -H localhost --livereload
```

If `bundle install` errors, delete [Gemfile.lock](Gemfile.lock) and retry.
Build output goes to `_site/` (gitignored).

## Configuration (`_config.yml`)

Key settings to know:

- `title`, `description`, `url`: Site identity
- `author.avatar`: Path to headshot image in `assets/images/`
- `author.links`: Array of sidebar social/contact links (label, icon, url)
- `author.bio`: Short bio shown in sidebar (supports HTML line breaks)
- `skin`: Currently `"dirt"` — other Minimal Mistakes options: `air`, `aqua`, `contrast`, `dark`, `default`, `neon`, `mint`, `plum`, `sunrise`
- `search: true`: Enables lunr.js client-side search
- `timezone: America/New_York`

## Custom Styling (`assets/css/main.scss`)

All customizations live in one file. Key overrides:

| Customization | Detail |
|---------------|--------|
| Base font size | `17px` (theme default is 16px) |
| Content max-width | `1000px`, centered |
| Avatar | `160px` circular, max-width overridden |
| Sidebar | Forced opacity `0.9` |
| Social icon colors | Platform-specific: LinkedIn `#0077B5`, GitHub `#181717`, ORCID `#A6CE39`, Google `#4285F4`, Brown `#4E3629`, email `#D44638` |
| Resume page font | Smaller font and tighter line-height for dense CV content |
| Link hover | `opacity: 0.7` at rest, `1.0` on hover |

The file starts with `@import "minimal-mistakes";` — all custom rules go after this import.

## SEO (`_includes/head-custom.html`)

Contains JSON-LD structured data (Schema.org `Person` type). Update this file when:
- Job title or affiliation changes
- Social profile URLs change
- New relevant profiles are added

## Adding Content

### New publication or talk
Edit `_pages/research.md` directly. Publications follow a consistent format with journal name, year, title, coauthors, and DOI link.

### Updating resume/CV
1. Add the new PDF to `assets/resumes/`
2. Update the filename references in `_pages/resume.md`
3. Update the filename in `_config.yml` author links if the CV link is there

### Updating the avatar
Replace the file in `assets/images/` and update the `author.avatar` path in `_config.yml`.

### Homepage news items
Edit `index.md` — the recent events section is a bulleted list, most-recent first.

## Deployment

Typically add and commit, do not push. DO NOT put any coauthorship ("coauthored by Claude" or anything like that). When the user pushes to `master` — GitHub Pages automatically builds and deploys. No CI/CD configuration needed beyond the GitHub Pages setting on the repo. The [CNAME](CNAME) file routes `pvankatwyk.com` to the GitHub Pages site. 


# CLAUDE.md — rule template
Here are 12 rules to keep in mind when making changes.

These rules apply to every task in this project unless explicitly overridden.
Bias: caution over speed on non-trivial work.

## Rule 1 — Think Before Coding
State assumptions explicitly. Ask rather than guess.
Push back when a simpler approach exists. Stop when confused.

## Rule 2 — Simplicity First
Minimum code that solves the problem. Nothing speculative.
No abstractions for single-use code.

## Rule 3 — Surgical Changes
Touch only what you must. Don't improve adjacent code.
Match existing style. Don't refactor what isn't broken.

## Rule 4 — Goal-Driven Execution
Define success criteria. Loop until verified.
Strong success criteria let Claude loop independently.

## Rule 5 — Use the model only for judgment calls
Use for: classification, drafting, summarization, extraction.
Do NOT use for: routing, retries, deterministic transforms.
If code can answer, code answers.

## Rule 6 — Token budgets are not advisory
Be careful with token usage.
Complete tasks but be mindful of the context length and usage.

## Rule 7 — Surface conflicts, don't average them
If two patterns contradict, pick one (more recent / more tested).
Explain why. Flag the other for cleanup.

## Rule 8 — Read before you write
Before adding code, read exports, immediate callers, shared utilities.
If unsure why existing code is structured a certain way, ask.

## Rule 9 — Tests verify intent, not just behavior
Tests must encode WHY behavior matters, not just WHAT it does.
A test that can't fail when business logic changes is wrong.

## Rule 10 — Checkpoint after every significant step
Summarize what was done, what's verified, what's left.
Don't continue from a state you can't describe back.

## Rule 11 — Match the codebase's conventions, even if you disagree
Conformance > taste inside the codebase.
If you think a convention is harmful, surface it. Don't fork silently.

## Rule 12 — Fail loud
"Completed" is wrong if anything was skipped silently.
"Tests pass" is wrong if any were skipped.
Default to surfacing uncertainty, not hiding it.
